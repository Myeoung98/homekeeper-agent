- (decision) Language: Python. Telegram library: python-telegram-bot (PTB) v21+ — chosen for built-in ConversationHandler, strong ecosystem
- (decision) Deployment: personal machine, polling mode (no public server). Catch-up on restart: on startup, query SQLite for overdue Tasks and send missed Reminders immediately
- (decision) Scheduler: simple background loop polling SQLite every minute for due Tasks — no APScheduler dependency
- (decision) Module structure: bot/ | scheduler/ | db/ | domain/ — bot and scheduler communicate only via DB (no shared in-memory state); domain/ is pure Python testable without Telegram or SQLite
- (decision) Database: plain sqlite3 (built-in) — no ORM; schema defined in SQL file; WAL mode enabled for concurrent access between bot thread and scheduler thread
- (decision) HITL enforcement: structural — no outbound integration module exists in codebase; bot/ only sends Telegram messages, never calls external APIs or services
- (decision) Conversation state: PTB in-memory ConversationHandler (default); restart mid-conversation = user restarts flow — acceptable for personal use
- (decision) AD-8 added: single writer for TASK.next_due_date — only bot/reminder_callbacks.py; scheduler re-reads row before logging to avoid stale-date race (found by adversarial reviewer)
- (decision) AD-6 clarified: catch-up uses REMINDER_LOG (not a last_reminder_sent column on TASK) as sole authority on send history
