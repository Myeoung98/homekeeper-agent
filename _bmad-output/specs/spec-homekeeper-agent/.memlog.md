updated: 2026-06-24T00:18

- (event) Spec created from PRD prd-Vibe-2026-06-23/prd.md (status: final)
- (capability) CAP-1: Admin manages recurring Tasks (create/view/edit/delete) via Telegram conversation
- (capability) CAP-2: Bot proactively delivers Reminders D-1 and D-0 to Admin and all Members; re-notifies hourly when overdue until confirmed
- (capability) CAP-3: Admin confirms Task completion; bot auto-reschedules next Cycle based on original due date
- (capability) CAP-4: Admin or Member reports ad-hoc Incident; bot returns matching Repairmen from curated directory within 30s
- (capability) CAP-5: Admin maintains Repairman directory and controls Member roster by Telegram user ID
- (constraint) HITL absolute: bot never contacts any external party or acts outside the conversation without explicit user confirmation — design principle, not technical limitation
- (constraint) Single interface: all interaction via Telegram only — no web dashboard, no mobile app
- (constraint) Single Admin per instance, identified by Telegram user ID; Repairman list is Admin-curated only (no external search)
- (constraint) SDD: every behavior flow must have written acceptance criteria before implementation
- (assumption) SQLite for local persistence; no cloud DB in v1 (user-confirmed)
- (assumption) Reminders sent at 08:00 Vietnam time (UTC+7); per-Task time customization deferred to v1.1 (user-confirmed)
- (assumption) Member enrollment: Admin registers family members by Telegram user ID via bot command (not yet confirmed)
- (assumption) Repairman service-type matching uses simple keyword match on free-text field; no LLM, no enum validation
- (event) Self-validate Pass 1+2 complete. Fixed: CAP-3 intent (removed HOW prescription), CAP-2 success (time-mock testable), skip flow added to CAP-3, Member UI constraint added to CAP-2, over-messaging counter-constraint added
